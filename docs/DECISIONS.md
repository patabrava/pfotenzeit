# Pfotenzeit — implementation decisions log

Each entry: what the package left open or ambiguous, what we chose, why. Reversible unless marked.

## D-001 Repository layout
Vite project at repository root, design package moved to `docs/pfotenzeit/` (00_START_HERE). The handoff ZIP stays untracked.

## D-002 Dependency versions (2026-10-09, npm registry)
three 0.186.1 / @types/three 0.186.0, vite 8.3.4, vitest 5.0.3, TypeScript 5.9.3, @playwright/test 1.64.0, fake-indexeddb 6.2.5, @gltf-transform/* 4.5.1, gltf-validator 2.0.0-dev.3.10. TypeScript 7.0.x exists but is the new native major; 5.9 is the proven line for Vite 8 tooling. Locked in package-lock.json.

## D-003 Care kinds
04 lists meal, rest and "ruhiges Spiel, bei Stress stattdessen Abstand". We model four kinds: `meal`, `rest`, `play` (comfort +20) and `calm` ("Abstand geben": stress −20, comfort +10). `calm` is offered instead of `play` when stress > 60 or arousal > 70. Balance values are initial defaults.

## D-004 Learning criterion storage
"Two independent helpful decisions in different scenarioIds per learning point" is stored as `helpfulScenariosByLearningPoint` and accumulates across visits. Learned ⇔ ≥ 2 distinct scenario ids. The learning mark is granted once (`rewardedLearningIds`). Only options with `countsForLearning: true` contribute (03: for L01 the distance and the pause decisions).

## D-005 Supported retry and inserted variant
An unhelpful option with `next: 'supportedRetry'` enqueues one supported replay of the same round (hint visible, decision counts as practice only, no energy cost). If, when the queue ends, the visit has used a supported retry and the learning point is still not learned, one unsupported re-run of the first failed round is inserted (max one per visit, `insertedRetryUsed`). Energy −4 applies once per round id in `completedRoundIds`, never for the supported replay.

## D-006 Visit closure semantics
`COMPLETE_VISIT{closure:'completed'}` after the last round, or `closure:'careClosure'` when (a) the chosen option has `next:'careClosure'`, (b) the real dog needs care (readiness ≠ ready) during the visit, or (c) at least one round was completed and the player ends the visit from the lesson menu. Otherwise ending is `ABANDON_VISIT` (no mark, no penalty). Any completed/care-closed visit counts the lesson in `completedLessonIds`.

## D-007 Offline minimum elapsed
Elapsed time below 60 s is ignored by `APPLY_OFFLINE` so that boot + an immediate focus event apply the loss exactly once (11: "zwei Rückkehrereignisse gleicher Sitzung").

## D-008 Active routes
Active care time accumulates only while visible, focused, unpaused, tab owner, and route is `home` or `lesson`, or `profile` while a care effect is being presented (04 Zeitmodell). The school sheet, settings, reflection, memorial and mode screens stop the clock.

## D-009 Loss check deferred during react
During `react` the tick still applies vitality changes, but the `lost` transition is only resolved once the phase leaves `react` (15: "gestartete atomare Wirkung abschließen, dann Verlustzustand anzeigen").

## D-010 3D assets are code-authored
No Blender or image-to-3D access in this environment. Characters are generated by `scripts/build-models.mjs` as rigged, skinned GLBs with the 08 skeleton and the 13-clip contract, exported through gltf-transform and checked with gltf-validator. Manifest status `code-authored`. This is above a placeholder but below final art; tickets A01–A09 stay open for a sculpted pass.

## D-011 Pixel sprites are data
Pixel states are authored as palette-indexed string grids in `src/ui/pixel/sprites.ts` and drawn to a canvas with integer scaling and nearest-neighbour. `scripts/export-pixel.mjs` emits PNGs for the manifest; runtime does not depend on the PNGs.

## D-012 Meta actions outside the reducer
`CREATE_SAVE`, `SELECT_MODE`, `ARCHIVE_CHALLENGE` span several saves and are handled by the store (`src/state/store.ts`), which closes the current save's time anchor (`CLOSE_APP`), switches, then applies `APPLY_OFFLINE` on the target. The reducer only ever sees one save.

## D-013 Revision ownership
The store increments `Save.revision` per committed action; the repository rejects commits whose revision is not newer than the stored one (`StorageError('conflict')`).

## D-014 npm cache
The sandbox denies writes to `~/.npm`. All npm commands use `npm_config_cache=$TMPDIR/npm-cache`. Not a project property; documented for reproducibility.

## D-015 Git
Creating `.git` is denied in the sandbox. The user initializes the repository (`git init -b main`) and commits; sessions do not run git.

## D-016 Duplicate check before semantic validation (WP-A)
A replayed transactionId answers `duplicate` with the identical save even if the action would now be semantically invalid (e.g. COMPLETE_VISIT after the visit is gone). Only the transactionId/nowUTC shape is checked first.

## D-017 Meaningful care closure (WP-A refinement of D-006)
Mid-visit `COMPLETE_VISIT{careClosure}` is accepted when ≥ 1 decision was made, or real readiness is `needs_care`, or the last option had `next:'careClosure'`. In `reflect` careClosure is always accepted; `completed` only when the queue is exhausted (else `not_meaningful`). `prepare` and `react` never accept COMPLETE_VISIT.

## D-018 careClosure option round
An option with `next:'careClosure'` moves to `reflect` immediately; the round costs no energy and is not listed in `completedRoundIds` (stopping is not an exercise round). `index` stays on the round so selectors still show it.

## D-019 Bond vs learning
Bond counts any helpful decision, including inside a supported replay. Learning counts only unsupported + `countsForLearning` (D-004).

## D-020 Inserted variant details
Inserted when the queue ends, some ref is supported, `!insertedRetryUsed`, and the lesson's learning point is not yet learned (save-level). `firstFailedRoundId` = roundId of the first supported ref. An unhelpful supportedRetry pick inside the inserted variant enqueues another supported replay (02: unlimited supported repetition); the inserted variant itself stays max once.

## D-021 Lost dog action matrix
NEXT_ROUND, SELECT_OPTION, COMPLETE_VISIT, CARE, START_VISIT → `dog_lost`. ABANDON_VISIT, ACKNOWLEDGE_EFFECT, BUY_UPGRADE, RENAME_DOG allowed. TICK_ACTIVE / APPLY_OFFLINE → applied no-op.

## D-022 ACKNOWLEDGE_EFFECT semantics
Matching id → clear pending (+ `react → feedback`). Pending exists but id differs → `invalid`. No pending → applied no-op. ABANDON_VISIT clears a pending presentation only if it contains a decision effect.

## D-023 Challenge pause
PAUSE/RESUME on standard → `challenge_only`; pausing twice is an applied no-op. CARE and NEXT_ROUND remain allowed while paused; only START_VISIT and ticks are blocked.

## D-024 Settings and tick validation
UPDATE_SETTINGS ignores unknown keys but rejects the whole patch (`invalid`) on an invalid value for a known key. TICK_ACTIVE with negative/NaN ms → `invalid`; 0 ms → applied, no change.

## D-025 Regeneration uses post-decline values
Per 15 order (decline, then check), satiety 36 → 34 does not regenerate in that minute.

## D-026 START_VISIT rejection order
dog_lost, visit_in_progress, unknown_lesson, invalid visitId/seed, challenge_paused, training_locked, needs_care.

## D-027 Sandbox `*token*` read-deny (environment, not product)
The sandbox denies reading any path matching `*token*`, which hits Vitest's API-token file and PostCSS's `tokenize.js`. Workarounds used: run tests with a throwaway `HOME` (`HOME="$TMPDIR/vhome" npm test`), avoid `@import`/`url()` in CSS (fonts are injected at runtime from `src/ui/fonts.ts`). Outside the sandbox none of this is needed.

## D-028 Playwright uses installed Chrome
Browser downloads are blocked (cdn.playwright.dev). `playwright.config.ts` uses `channel: 'chrome'` (Google Chrome is installed). Inside the sandbox Chrome cannot bind its singleton socket, so e2e must run outside the sandbox.

## D-029 Renderer colour pipeline (WP-D)
`NoToneMapping` + `SRGBColorSpace`; lights budgeted so direct + fill ≤ π so the flat 06 palette is not desaturated. Shadows off on low tier, 1024 PCFSoft on high; contact-shadow blob under every actor. School view frames the core yard (training circle, shelter, rest deck) rather than the full fence.

## D-030 Pixel adult mapping (WP-B)
`growthStage:'adult'` (schema only, not reachable in the MVP) maps to the growing pixel art.

## D-031 Service worker build (WP-C proposal, adopted)
`src/sw.ts` is a second Rollup input emitted as `sw.js`; `build.manifest: true` lets the worker precache the hashed shell atomically. Registration only in production over https/localhost; update applied only outside a lesson after a successful commit.

## D-032 Browser verification fixes (2026-10-09)

Banner text does not intercept controls; banner buttons remain interactive. First service-worker activation claims the page without reloading; later controller changes retain the update reload. Production offline verification covers first installation without a preceding online reload. Debug metrics await the renderer handle instead of racing an immediately resolved null. ## D-033 Dog skeleton extension for eyelids and gaze (creative milestone)
08 lists "Lider als zwei Bone- oder Morph-Ziele, Augenblickrichtung separat". The code-authored dogs add six bones under `head`, in this order after `jaw`: `eye_l`, `eye_r`, `eyelid_upper_l`, `eyelid_upper_r`, `eyelid_lower_l`, `eyelid_lower_r` (32 bones total; ear/tail/leg names unchanged). Clips may animate them (blink, gaze toward the handler, heavy lids when tired). `scripts/validate-assets.mjs` expects exactly this list for dog GLBs; the renderer does not depend on bone count, only on clip names. The procedural fallback rig stays as it is. Loader/validator changed together as required by the handoff section 6.

## D-034 Camera framing targets
`closeup`: focus dog fills 55–65 % of portrait viewport height, elevation 22–28°, front three-quarter so eyes and tail are visible, all paws/ears/tail inside with ≥ 6 % margin. `lesson`: 40–50 %. `school`: frames the training circle, shelter front and rest deck with Nala at the lower-middle third at ≥ 18 % of viewport height; the full fence is not required (06: focus on the playing dog). Landscape keeps the same subject share by height. The renderer check (`src/render/dev/renderer.check.ts`) asserts these numbers.

## D-035 Reaction choreography timing
Decision → camera accent 250–400 ms toward the focus dog → reaction clip → ≤ 600 ms settle → feedback. Reward glint plays at the header mark counter, never over the dog (05). Reduced motion: instant pose, instant card, same texts. No step adds a mandatory wait beyond the clip itself; `maxDurationMs` stays the UI's upper bound.

## D-036 Art direction change: sourced hero model, textured asset contract (2026-10-09 evening)
Per `docs/HANDOFF_PREMIUM_ASSET_SOURCING.md` (priority over sheet fidelity): the user rejected the code-authored character results; the next hero Nala is to be a professionally authored, licensed model (candidate A: Golden Retriever Puppy, TurboSquid, pending the user's license confirmation and purchase). Consequences: (1) live dog/human GLBs are not regenerated merely to match the old sheets; the procedural tier stays the fallback. (2) The loader and validator are adapted together to a **textured contract**: manifest entries declare `material: 'vertex' | 'textured'`, `textures: [{slot, width, height, bytes}]` with budgets (dog ≤ 2 × 1024², total texture bytes ≤ 6 MB decoded estimate per character, ≤ 3 draw calls per character), `rig: 'project' | 'vendor'` and, for vendor rigs, `clipMap: Record<SemanticClip, string>` mapping the 13 semantic dog clips (5 human) to vendor clip names; the validator checks semantic coverage, influences ≤ 4, metres/+Y/+Z forward, and texture budgets. (3) `scripts/ingest-vendor.mjs` normalizes a vendor GLB (prune, dedup, texture resize, measurement, report) into `art/staging/<asset>/` and never writes to `public/` by itself. (4) No purchase, seller contact or dependency without the user's authorization.

## D-037 Blender runs only outside the sandbox
Blender 5.2.2 is installed with the official MCP bridge (`docs/BLENDER_CONNECTION.md`) but headless Blender segfaults inside the Claude sandbox (exit 139, GPU access denied). Clip authoring, retargeting and `.blend` edits are therefore outside-the-sandbox steps; the Node pipeline (gltf-transform, validator, loader) is the in-sandbox part.

## D-038 Manifest field names for the textured contract (final, 2026-10-09)
WP-G2 finalized the D-036 schema; the loader, validator and build script use exactly these names: `material` ('vertex' | 'textured'), `textures` ([{slot, width, height, bytes, mime}], slot ∈ baseColor | normal | metallicRoughness | occlusion | emissive), `textureSizes` (legacy max side per texture, kept), `drawCalls`, `rig` ('project' | 'vendor', **string**), `rigInfo` ({joints, maxInfluences, root}), `clipMap` (semantic → file clip name), `clips` (always the semantic 13 / 5), `sourceClips`, `missingClips` (only when unresolved), `productionIntegrated`, `clipMeta`, `measuredShoulderHeightM` / `measuredHeightM`. Defaults: absent `material` = vertex, absent `rig` = project, absent `clipMap` = identity, absent `drawCalls` = 1. The legacy object form `rig: {joints, maxInfluences}` written by the previous build script is replaced by `rig: 'project'` + `rigInfo` in `scripts/build-models.mjs` and in the live manifest (patched in place, no GLB regenerated); the validator keeps treating a non-string `rig` as project for old files. Staging note: the five textured Blender reference candidates validate (0E/0W/0I) but total 9.25 MB, above the 8 MB live budget; what ships up front is decided with the hero model, not by this decision.

## D-039 Framing targets amended after measurement (WP-H, 2026-10-09)
Measured with the bounds-driven CameraRig (deformed-surface samples, front three-quarter on the handler's side, elevation ≤ 28° closeup / ≤ 34° lesson): (1) the standing procedural puppy silhouette is never narrower than ≈ 0.76 wide:tall from a front three-quarter, so on 9:16–9:19.5 portrait the uncropped maximum is 52–55 % standing and 41–50 % lying. Decision: keep elevation and margins, no paw cropping; D-034 closeup reads 55–65 % at aspect ≥ 0.6, and ≥ 50 % standing / ≥ 40 % lying (≤ 65 %, margin ≥ 6 %) in portrait. The sourced hero is expected to reach the full band (the staged textured candidate measures 60.1 % at 390×844). (2) "Nala ≥ 18 %" in the school view fixes the frame at ≈ 1.9 m height while the core yard (training circle, shelter front, rest deck) needs ≈ 4.5 m, leaving a 0.9 m strip of sand in portrait. Decision: school share ≥ 10 % portrait / ≥ 14 % landscape with Nala in the lower-middle third and the circle centre, shelter front and rest deck asserted inside the frame; the school view's job is the place and the upgrades (06), closeup and lesson give the dog. Lesson targets (40–50 %, strip sizes from D-032) are unchanged and met.

## D-040 Character texture budget corrected; ingest output location; clip events from clipmap (2026-10-10)
D-036 said "dog ≤ 2 × 1024², total texture bytes ≤ 6 MB decoded estimate"; the two are inconsistent because one 1024² RGBA map with mips is already ≈ 5.32 MiB by the validator's own estimate (w·h·4·1.33). Decision: per character the decoded estimate cap is **12 MiB** (two 1024² maps at most, e.g. baseColor atlas + normal), per-texture cap stays 1024², PNG/JPEG only; environment rules unchanged. `scripts/lib/assetContract.mjs` is updated accordingly (WP-N follow-up). The design package's `08_3D_ASSET_HANDOFF.md` ("1 × 1024 Atlas", "≤ 45k" for the yard) is the historical brief; D-036/D-038/D-040 and the validator are the binding contract, the package text is not edited. Ingest output may be any directory outside `public/`: `art/staging/<name>/` for test inputs, `art/vendor-evaluation/<vendor>/<asset>/staged/` for licensed files. `clipmap.json` may carry per-semantic `events` (e.g. `eat.treat_received`) that ingest writes into `clipMeta`; the renderer reads events from the manifest, so a vendor eat clip with a different contact moment needs no code change.
Status 2026-10-10: applied during the user-requested verification and pending-item resolution. The shared cap is 12 MiB, ingest accepts string/object clipmaps and finite event overrides, output remains forbidden inside public/, and validation requires strictly interior event times plus eat.treat_received. `node scripts/dev/verify-d040.mjs` passes positive and negative CLI cases. The historical session's classifier denial did not carry forward into this authorized integration run.
